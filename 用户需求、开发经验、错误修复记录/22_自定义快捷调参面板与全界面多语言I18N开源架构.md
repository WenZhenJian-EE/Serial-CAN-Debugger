# 第22章：自定义快捷调参面板与全界面多语言I18N开源架构

## 1. 业务痛点与用户诉求演进

在实际嵌入式控制、电源数字化（LLC/PFC/BUCK）与电机控制（FOC/BLDC）调试过程中，用户对交互体验提出了进一步的工程诉求：

1. **历史初版自定义调试按钮与 PI 调参功能重塑**：
   > “并且我原来这个软件最开始那个初版，那些自定义的按钮功能呢？怎么没有啊？这些自定义的调试按钮功能。你说我调节 PI，就点两个按钮就 OK 了”
   - 在上位机初版（PyQt5）中曾实现过按键网格与调参滑动条（`custom_buttons.py`）；
   - 在现代 MAP 2.0 极速引擎中，必须重构这一核心生产力工具，让工程师在实时观察波形动态响应的同时，能方便地发送自定义指令（例如调节 PI 参数、启停电机、发送 Hex 握手等）。

2. **面板位置重构：下沉至左侧边栏底部空白区域**：
   > “把这个按钮界面放到下面吧，没发现我现在下面栏目很空吗？都放到下面空白的地方。”
   - 原先将调参放在侧边栏第三个顶栏 Tab（串口 / CAN / 快捷调参），切到调参页就看不到当前的串口或 CAN 连接配置；
   - 经实机考量与用户示意，将顶部 Tab 还原为纯净的 **串口总线 (UART)** 与 **CAN 总线 (CAN/FD)**；
   - 将自定义控制面板常驻**下沉至侧边栏下半部分空白区**，无论当前激活的是串口还是 CAN，下方均可同时操作自定义按钮与滑块。

3. **零预设强加·用户自主命名与指令自由配置**：
   > “另外，每个按钮的名称你不用帮我起，也不用帮我预设，做成自定义的形式就行（名称我自己来起）。每个按钮对应的指令也是，不用帮我预设，我点一下就发送对应的指令即可。”
   - 坚决杜绝“先入为主”的写死预设（如强加固定的 PID、电机指令等）；
   - 保持控件面板的纯粹自定义性：空状态下提供快速添加卡片，按钮名称、发送指令（ASCII / HEX）、目标总线由用户自由填写。

4. **按钮与滑块双形态融合**：
   > “如果可以的话，某些按钮希望能支持改成滑块的形式”
   - 支持在配置对话框中自由切换【按钮】或【滑块】类型；
   - **按钮模式**：点击触发，高亮触感反馈，支持 HEX 与 ASCII 字符串；
   - **滑块模式**：支持连续拖动与微调步进（`[-]` / `[+]` 步进器），支持自定义数值模板（如 `P={val}\r\n`），内置 80ms 节流下发机制，防止高频滑动阻塞硬件总线。

5. **全软件界面中英文一键无刷新即时切换（i18n）**：
   > “还有这个软件能否全面支持英文呢？就一键中英文切换是否支持呢？”
   - 打造无第三方库包袱的响应式微内核 `i18n.js`，支持 `zh-CN` 与 `en-US` 毫秒级双向无刷新切换，本地持久化。

6. **字体零内嵌规范与开源作者/博客个人信息集成**：
   > “所有内容字体不要内嵌，我希望能全面支持中英文切换，因为我后面这个是要开源出去的，要加上我个人的信息（比如说我 GitHub 上博客的信息等等）”
   - **字体零内嵌**：严格禁止引入 `.woff`/`.ttf` 等外部字体文件，完全依托宿主操作系统原生字体渲染栈；
   - **开源作者与主页信息展示**：在软件导航栏与系统信息弹窗中直观展现作者 **温振键 (WenZhenJian-EE)**、开源仓库地址、个人主页与技术博客链接。

## 2. 纯粹自定义控件面板（CustomButtonsPanel）架构实现

### 2.1 侧边栏双层常驻布局
在 `webui/src/App.vue` 中：
- 顶部导航仅保留 `串口总线` 与 `CAN 总线` 两个硬件选项卡；
- 侧边栏内容区垂直流式排列：
  ```html
  <div class="sidebar-content">
    <SerialPanel v-show="sidebarTab === 'serial'" ... />
    <CanPanel v-show="sidebarTab === 'can'" ... />
    <CustomButtonsPanel
      :activeBus="sidebarTab"
      :isSerialConnected="connectionStatus.serial.connected"
      :isCanConnected="connectionStatus.can.connected"
      @toast="showToast"
    />
  </div>
  ```
- 既充分利用了左侧边栏底部的闲置纵向空间，又实现了上下位机硬件通信参数与控制指令的同屏并发操作。

### 2.2 响应式智能网格排布 (Hybrid CSS Grid)
侧边栏有效宽度约 350px，混合排布策略如下：
- 容器采用双列网格 `grid-template-columns: 1fr 1fr; gap: 6px;`；
- **按钮控件**：每行容纳两个紧凑按钮卡片，包含按钮名称、编码格式标记（HEX/ASC）与轻量编辑图标；
- **滑块控件**：自动声明 `grid-column: 1 / -1;` 独占整行，容纳当前读数、`[-]` / `[+]` 步进按钮与宽幅原生滑动槽；
- **常驻添加插槽**：独占整行，点击即可唤起配置弹窗。

### 2.3 弹窗配置与数据结构
每个自定义控件的存储模型如下：
```typescript
interface CustomControl {
  id: string;             // 唯一 ID
  type: 'button'|'slider';// 控件类型
  name: string;           // 用户自定义名称 (如 P+, P-, 启动, 速度)
  target: 'auto'|'serial'|'can'; // 发送目标通道 (Auto 自动跟随当前侧边栏总线)
  // 按钮专属
  data?: string;          // 发送载荷 (如 "SET P=1.0\r\n" 或 "A5 01 02 5A")
  is_hex?: boolean;       // 是否以十六进制字节下发
  // 滑块专属
  min?: number;           // 最小值
  max?: number;           // 最大值
  step?: number;          // 微调步进值
  value?: number;         // 当前设定值
  template?: string;      // 下发模板，如 "P={val}\r\n"
}
```

### 2.4 总线下发与防拥塞节流
1. **自动路由**：当目标设为 `auto` 时，若工程师当前正在看串口，则下发至串口；若正在看 CAN，则下发至 CAN 总线；亦可强制指定 `serial` 或 `can`；
2. **滑块高频防抖/节流**：通过闭包字典 `throttleTimers[ctrl.id]` 限制下发间隔为 80ms，杜绝连续拖动时瞬时冲垮硬件波特率或底层 FIFO 缓冲；
3. **JSON 导入导出**：支持一键导出 `custom_controls.json` 并在任何设备上一键恢复配置。

## 6. 踩坑复盘：按钮点击误触发配置弹窗与指令必填校验

### 6.1 异常现象
用户在控制面板上配置并添加了按钮后，期望点击按钮立即下发指令，但实际点击后依然弹出了“配置自定义控件”的弹窗：
> “我现在配置好的按钮不是点击发送吗？为什么我现在点击之后，还是弹出来配置这个界面呢？”

### 6.2 根因分析（Root Cause）
1. **指令空值静默保存（缺少必填校验）**：
   - 之前在配置弹窗中，输入框的 Placeholder 提示为“`如: SET P=1.2 或 A5 01 02`”；用户容易误以为这是默认填入的参数，直接点击了“保存生效”；
   - `saveControl()` 未对 `form.data` 是否为空做强校验，直接保存了一个 `data: ""` 的空指令按钮。
2. **点击事件劫持漏洞（Click Hijacking）**：
   - 在 `onButtonClick(ctrl)` 中曾存在保底逻辑：`if (!ctrl.data) { openEditDialog(...); return; }`；
   - 导致用户点击一个实际未写入指令的按钮准备下发时，系统误将点击动作转为了“打开配置编辑”，让用户产生了“为什么点发送却总是弹配置”的困惑。
3. **编辑齿轮弱可见**：
   - 齿轮图标常态透明度仅为 `0.3`，导致用户未能直观识别“点击主体=发送，点击齿轮=配置”的交互分工。

### 6.3 修复措施与架构升级
1. **解耦点击下发与配置弹窗**：
   - 彻底移除了 `onButtonClick` 中的 `openEditDialog` 调用！按钮点击永远专职负责指令下发；
   - 若检测到按钮 `data` 为空，坚决不弹模态窗，而是弹出精准黄色 Toast 警示：`按钮 [xxx] 尚未配置发送指令！请点击右侧齿轮 ⚙ 设置`。
2. **保存拦截与必填约束**：
   - 在配置弹窗中明确标记 `发送指令 (必填) *`；
   - 在 `saveControl` 中增加强行拦截校验：若指令为空，立即拦截并提示 `请填写发送指令内容（必填项）`，防止保存空指令按钮。
3. **状态可视化与齿轮常态高亮**：
   - 按钮卡片右上角若检测到指令为空，自适应显示醒目的黄色 `[未填指令]` 警示微标，提醒用户该按钮尚无有效载荷；
   - 齿轮编辑按钮透明度提升至 `0.6`（悬停时高亮至 `1.0` 且带主题蓝微光），明确传达齿轮为专属编辑入口。
